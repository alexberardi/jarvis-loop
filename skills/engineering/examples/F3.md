# F3: item titles are at most 120 characters

Goal: `pipeline.NewItem` refuses a title longer than 120 characters (after trimming) with
`CodeInvalidField` and the message `title is at most 120 characters`. Count characters (runes),
not bytes.

## Steps (in order)

1. `internal/pipeline/pipeline.go`: next to the other limits near the top of the file (search
   for `const (` blocks), add `MaxTitleRunes = 120` with a one-line comment
   (`// MaxTitleRunes is the longest item title, in characters.`).
2. In `NewItem` (line ~194), after the empty-title check, add:
   ```go
   if utf8.RuneCountInString(title) > MaxTitleRunes {
       return Item{}, errf(CodeInvalidField, "title is at most %d characters", MaxTitleRunes)
   }
   ```
   and add `"unicode/utf8"` to the imports (stdlib group, alphabetical).
3. Check whether a title can also be changed after creation: search pipeline.go for a function
   that sets `it.Title` (e.g. `ApplyPatch`). Apply the same check there with the same message.
4. Tests in `internal/pipeline/transitions_test.go` next to `TestNewItemDefaults` (line ~575):
   add `TestNewItemTitleLength` covering: exactly 120 ASCII characters → ok; 121 → CodeInvalidField;
   120 multi-byte characters (e.g. strings.Repeat("é", 120)) → ok (proves runes, not bytes);
   leading/trailing spaces don't count (a 120-char title padded with spaces → ok).
   If you changed ApplyPatch in step 3, add the same 120/121 cases for it.
5. The API maps CodeInvalidField to 400 already; add one case to the API's add-item test
   (search `internal/api/*_test.go` for a test that posts to `/items` with a bad priority and
   copy that pattern) asserting a 121-char title gets 400.
6. `go vet ./... && go test ./...` until green.

Commit: `items: titles are at most 120 characters`.
