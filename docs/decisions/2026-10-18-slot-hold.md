# The last agent slot is held for Mac work while a Mac item can run (2026-10-18)

Item #192. The dev box runner ran with `slots` 5 under `active_agents` 6 so a Mac runner always had
a slot. When no Mac item could run (on 2026-10-17 #61, #63 and #121 all waited on #94's QA), that
sixth slot sat idle.

## Decision

loopd holds a free slot for a resource R only while a runner taking only R has work
(`pipeline.SlotHolds`, applied in `pipeline.ChooseWork`):

- **(a)** a runner whose `only_resources` has R was seen (a claim or heartbeat, `runners.last_seen`)
  within two of its poll intervals. The runner sends `poll_seconds` with each claim; loopd keeps it
  in `runners.poll_seconds` with `only_resources` (migration 0019). 0 means 30 s, the runner's
  default.
- **(b)** an item needing R is claimable now by that runner: `Choose` run with its claim (its
  capabilities, only R, and the work stages it takes) returns one. Dependencies, leases and the
  resource and stage limits stay in one rule. The runner sends its configured stages
  (`runner_stages`, the work ones from `stages`) with each claim from either lane, since a lane's
  own `stages` is only part of them; loopd keeps them in `runners.stages`. So a Mac that takes
  build and review (the runbook's) holds nothing for a `macos` item in triage or land, which it
  would never claim. A runner that did not say counts as taking every work stage.
- **(c)** the claim at hand does not take an item needing R. When the slots left are all held, a
  claimant that can serve a held resource is given that work (even when it would have picked
  something else first); one that cannot gets nothing.

Each R holds at most one slot, and the slots held never outnumber the free ones (several resources
are taken in name order). Turns are held from too: a plan or orchestrate turn takes a slot like an
item. With nothing to claim the API still answers 204; `Work.Held` carries the reason ("slot held for
macos work") for tests, and the board's Runners panel recomputes the holds at render time
(`store.Runners`), so there is no new state.

Then the dev box's `slots` can equal `active_agents` again.

## Not done

- loopd does not know how many slots a Mac runner has free: a Mac busy with its own slots still
  counts as around (its heartbeats). The `macos` limit of 1 keeps that from holding a slot the Mac
  cannot use.
- The claim's 204 carries no reason for the runner; the runner only needs "nothing".
